## 5. UNSW 전체 컬럼 목록 (45)
```
id, dur, proto, service, state, spkts, dpkts, sbytes, dbytes, rate, sttl, dttl,
sload, dload, sloss, dloss, sinpkt, dinpkt, sjit, djit, swin, stcpb, dtcpb, dwin,
tcprtt, synack, ackdat, smean, dmean, trans_depth, response_body_len, ct_srv_src,
ct_state_ttl, ct_dst_ltm, ct_src_dport_ltm, ct_dst_sport_ltm, ct_dst_src_ltm,
is_ftp_login, ct_ftp_cmd, ct_flw_http_mthd, ct_src_ltm, ct_srv_dst,
is_sm_ips_ports, attack_cat, label
```
공식 정의(NUSW-NB15_features.csv)로 확인한 핵심 컬럼:
- `proto` = Transaction protocol (tcp/udp/… 문자열)
- `state` = 연결 상태 (ACC, CON, ECO, FIN, INT, REQ, RST … — **플래그 카운트 아님**)
- `smean`(=smeansz) = src가 보낸 흐름 패킷 크기 평균 / `dmean` = dst 패킷 크기 평균
- `sinpkt`(=Sintpkt) = Source interpacket arrival time (mSec) / `dinpkt` = Destination interpacket arrival time
- `synack` = SYN↔SYN_ACK 사이 TCP 연결 설정 **시간**(플래그 아님) / `swin/dwin` = TCP 윈도우 / `sttl/dttl` = TTL

## 6. 우리 6 feature 매핑 표
| 우리 feature | 의미 | UNSW 대응 컬럼 | 상태 | 대체 후보 / 주의 |
|---|---|---|---|---|
| proto | 프로토콜 종류 | `proto` | **정확(의미)** | 단 문자열('tcp'/'udp'…) → 코드 변환 필요(CIC는 숫자 6/17). |
| syn | SYN 플래그 존재(이진) | **없음** | **대응 없음** | 불확실 대체: `state`(REQ/CON/FIN…) 또는 `synack>0`(핸드셰이크 발생). 의미 상이 — 억지 매핑 금지. |
| psh | PSH 플래그 존재(이진) | **없음** | **대응 없음** | UNSW에 PSH 정보 자체가 없음. 깨끗한 대체 없음. |
| size | 패킷 길이 평균 | `smean` (+`dmean`) | **근사** | src 평균 패킷 크기. CIC "Pkt Len Mean"(전체)과 방향성 차이. |
| fwd_iat | 순방향 도착간격 평균 | `sinpkt` | **근사~정확** | Source interpacket arrival time = 순방향(src→dst) IAT. 의미 강하게 일치. |
| flow_iat | 전체 흐름 도착간격 | **단일 컬럼 없음** | **근사** | `dinpkt`(역방향), 또는 `sinpkt`+`dinpkt` 조합, 또는 `rate`(pkts/s) 역수. |

정리: 6개 중 **정확 1(proto, 포맷변환)** / **근사 3(size, fwd_iat, flow_iat)** / **대응 없음 2(syn, psh)**.
사전 추정대로 **TCP 플래그(syn·psh)와 flow_iat 대응이 가장 불확실**했고, 실제로 플래그 2개는 UNSW에
직접 컬럼이 없음(state/synack는 의미가 다른 시간·상태 지표).

## 8. 매핑 가능성 결론
**현재 인코딩을 그대로는 쓸 수 없음 — 조정 필요(일부 feature 대체 필요).**
- proto: 문자열→코드 매핑만 추가하면 사용 가능.
- size→`smean`, fwd_iat→`sinpkt`: 근사 사용 가능(방향성 차이 명시 필요).
- flow_iat: 단일 대응 없음 → `dinpkt`/조합/`rate` 중 택일(다음 단계 결정).
- **syn·psh: UNSW에 플래그 카운트 부재 → 직접 대응 없음.** 선택지(다음 단계/웹 AI 결정):
  (a) 두 비트를 빼고 10비트(1024상태) 인코딩으로 축소, 또는
  (b) state/synack 등에서 파생한 이진값으로 대체(단 PSH는 진짜 대체가 없음, 의미 변질 위험).
- 즉 12비트 인코딩을 UNSW에 그대로 이식 불가. 최소한 **플래그 2비트 처리 방침 결정 + 연속값 컬럼
  재매핑**이 선행되어야 재현 진단 가능. (이번 작업에서 인코딩 변경·구현은 하지 않음.)
