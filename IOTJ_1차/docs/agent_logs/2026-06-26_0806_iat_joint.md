# 시간축(IAT) feature 추가 후 HOIC의 joint vs marginal 재측정 (학습 없음)

- **작성일시**: 2026-06-26 08:06 (로컬), 실행 08:07
- **작성 주체**: 로컬 Claude Code agent (default mode)
- **작업 성격**: 진단 스크립트 1개 + json/png. **QCBM 학습 없음. 기존 소스 무수정(import 재사용).**
- **결론 선요약**: ★ **가설 부활.** IAT(시간축) 추가 시 joint 이득이 단조 증가(+0.003→+0.013→**+0.052**). marginal은 ~0.87 천장, emp_joint만 0.881→0.926으로 상승.

---

## 1. 작업 목적

핵심 가설 "joint > marginal"이 지금까지 미지지(Infiltration·DDoS 모두 joint 이득 ~0). 기존 4 feature(proto/syn/psh/size)는
모두 "패킷 자체" 속성이라 상호작용이 약했을 가능성. **시간축(IAT)을 추가하면 "패킷 속성 × 시간 간격"의 다른 축 조합이
joint 상호작용을 만드는지** 마지막 점검. 대상 = HOIC(emp_joint 0.88, 천장 아님). LOIC-UDP(0.997)는 천장이라 제외.

판단 기준(작업 지시): joint 이득(emp−marg) ≥ **+0.02** 이면 가설 부활/IAT가 핵심, 0 근처면 'joint≈marginal'로 종결.

- 비트 패킹: 기존 8bit(MSB) 뒤(LSB)에 IAT 비트 추가 → `state = (state8 << iat_bits) | iat` (순서 명시).
- 평가: `auc_score`(raw MWU, 방향반전 없음) 그대로. 모든 raw AUC ≥ 0.5라 1−AUC 불필요.

## 6. 사실 기반 관찰 (최종 판정은 웹 AI)

1. **joint 이득이 IAT 추가에 따라 단조 증가**: +0.0032 (A) → +0.0130 (B1) → **+0.0518 (B2)**. 판단 기준(+0.02)을 **B2에서 명확히 초과** → **가설 "joint > marginal" 부활. IAT(시간축)가 핵심 동인.**
2. **marginal은 ~0.87에서 사실상 천장**(0.8775→0.8726→0.8741, 거의 불변). 반면 **emp_joint는 0.8807→0.8856→0.9258로 상승**. 즉 시간축 feature가 **marginal로는 못 담는 결합 구조**를 추가함 → "패킷 속성 × 시간 간격" 상호작용 실재.
3. **희소성 주의**: 점유율이 9.4%→7.7%→**2.3%**로 급감(B2는 4096상태 중 94개만). 그럼에도 emp_joint AUC가 **오히려 상승**한 것은, 희소성이 결과를 marginal로 수렴시키지 않고 **joint 정보가 실제로 분리에 기여**함을 시사(희소성 artifact로 보기 어려움). 단 emp_joint는 train joint를 "외운" 상한이므로, 이 이득을 **QCBM이 실제로 학습 가능한지는 별도 검증 필요**.
4. logp 격차(emp)도 4.77→4.89→**8.05**로 커짐 — joint 분포에서 공격이 훨씬 더 낮은 확률을 받음(분리 강화)과 정합.

> 함의(사실): 지금까지 "joint≈marginal"이었던 이유는 feature가 모두 같은 축(패킷 속성)이라 상호작용이 없었기 때문. **다른 축(시간 간격)을 더하자 joint 이득이 나타남.** 연구 서사가 'joint/marginal 등가 종결'에서 **'적절한 다축 feature에서 joint 우위 입증'** 으로 전환 가능.
